# Check exceptions and linked correction (P25-S3)

Canonical `Txn`/`TxnSplit` remain the sole ledger and instrument authority. Reconciliation owns cleared state. The Checks / Exceptions tab in Bank Reconciliation reads the company’s structured CHECK lines, including earlier-period outstanding instruments. Select all banks or one configured bank, a review-through date and an optional issued-on/before age cutoff. The cutoff is an operator review criterion, never a statutory expiry or accounting rule. Multi-fund bank allocations with the same transaction/account/reference aggregate into one instrument amount.

The report shows outstanding/cleared instruments, missing issue/delivery facts, missing external supporting evidence references, age-review candidates, cancelled original/reversal/replacement relationships, imported statement ERROR rows, and unresolved amount/date/cleared-state/duplicate differences in unfinalized reconciliation sessions. Recorded explanations remain visible without being treated as resolution. Bank differences navigate to their existing session. Bank ERROR facts remain owned by Bank Transactions/import review. No new bank-error authority is created.

If Journal reverses a cancellation reversal, exception history labels CANCELLATION_REVERSED and requires review of the full dated chain; it does not silently describe the instrument as extinguished or replay a stale action.

Correction lifecycle is dated from canonical reversal/replacement relationships through the selected cutoff. Current payment/review facts are shown; this is not an immutable historical metadata snapshot. Cleared state is counted only when its recorded cleared date is through the cutoff. An undated legacy cleared fact does not prove it was cleared at that historical date. External references identify supporting material; the application does not verify the referenced material exists or contains an approval/signature. No attachments or approval queue are introduced.

Record Review requires a factual note and review date. It updates delivery date, evidence reference, review date and note on every allocation of the selected instrument and writes before/after audit atomically. Issue/reference/amounts and bank-cleared facts do not change. Blank evidence or delivery retains an explicit missing-fact exception. Closed-period and finalized/completed reconciliation protection applies; retained cancelled history cannot be changed. Journal save/copy/load preserves review facts. Clearing all payment facts deliberately clears the optional review facts under ordinary direct-edit policy and retains the before/after audit.

Void is an explicit canonical reversal of the selected whole transaction, on an open selected date, with a required cancellation explanation and confirmation. The operator decides that cancellation is valid; old age is never sufficient justification inferred by the application. For mixed instruments, this reverses the whole transaction, as the confirmation explains; use Journal correction to separate the accounting decision where needed. Reissue accepts only one outgoing CHECK instrument, possibly allocated across several funds. Mixed bank payments are rejected before writing. Reissue creates a reversal and an unchanged-allocation replacement in one transaction, sets `replacementFor`, and requires a different new number and issue date. The old check remains reserved; the new number must be unused for the issuing account. New delivery and review facts start unknown; evidence is supplied explicitly, not copied as proof of new delivery. The original, reversal and replacement retain both references and their relationship. Original expense + opposite reversal + replacement equals one expense. Failure, duplicate reference and concurrent retries cannot leave a partial correction.

Completed/finalized reconciliation prevents correction. A cleared or matched check must be reviewed in reconciliation before reissue. Linked check correction history cannot be directly edited/deleted through either Journal command service. The current replacement can be reversed/reissued again, retaining the chain. Generic reverse-and-replace remains blocked for referenced payments because it cannot choose a new instrument identity. Reconciliation shows check/reference and correction-history columns without marking cancelled pairs cleared or auto-matching them. Cancellation pairs still contribute their dated signed bank effects to the existing balance calculation.

## D04 policy boundary

The adopted program explicitly leaves runbook §5.12 stale-check income versus §11.3 expense reversal and continuing legal obligations unresolved. This slice supplies factual age review and explicit ordinary cancellation/reissue only. It never voids, recognizes income, reverses expense, releases a payable or marks a bank line cleared solely because an instrument is old. No stale-triggered accounting action is available. The accounting authority must resolve D04 before such an action can be implemented. This boundary fulfills S3’s acceptance rule that age alone does not extinguish a valid obligation; it does not resolve the pending policy.

## Persistence and portability

Replay-safe nondestructive V80 adds nullable evidence reference (500 characters), review date and review note (1000 characters) to canonical bank splits. Legacy facts remain unknown. Database constraints require a review note for a review date and prohibit orphan review facts without a payment method. Before/after audit participates in the same transaction.

SCLX `paymentReferences` version 2 adds exactly `evidenceReference`, `reviewedOn`, `reviewNote` to each version-1 line fact. Null remains unknown and dates remain ISO. Version 1 imports without fabricated review data; version 2 exports all current facts. Normalized review facts participate in preview conflict identity; all-null new fields preserve version-1 identity. Canonical correction relationships already transport original/reversal/replacement links. Import restores those links before applying payment facts and reference reservations. Reimport remains idempotent. No local IDs are exported as portable relationships. External exporters are not changed. Whole-database backup retains the complete existing audit history.

Donor review found legacy header-level `check_number` and a separate `LedgerMatchRecord` mapping. Neither is imported: they would regress per-bank identity or duplicate the production reconciliation authority. The existing canonical correction graph and payment-reference extension are deliberately extended instead.
