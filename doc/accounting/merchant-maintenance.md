# Merchant maintenance

P24-S4C maintains the existing Merchant master. Merchant is an optional independent reference on each canonical TxnSplit; it is not the transaction-header Payee or a Fund, Event or Budget Category. Database and portable IDs survive rename/deactivation. The existing SCLX parties extension carries merchant identity, name, notes, active state and exact split relationships.

MerchantAdminService lists only the active company's records, including inactive rows. Save requires BOOKKEEPING_WRITE before persistence, locks the selected company and exact existing merchant, validates ownership and a required trimmed name of at most 200 characters, and rejects case-insensitive trimmed-name duplicates, including inactive rows. Existing database company/name uniqueness remains a final safeguard. Create/update and authenticated before/after audit commit together or roll back together. Unknown IDs, unauthorized or cross-company edits fail without adopting an unowned historical record. Existing imported duplicates remain readable but need distinguishable names before editing.

All merchants are retained instead of physically deleted to protect transaction, audit and portable interchange history. Clear Active and save to remove a merchant from new Journal choices. Existing inactive assignments remain readable/editable as historical references. Refresh resolves active labels by stable ID and preserves inactive assignments and unsaved drafts. Two lines in one transaction may retain different merchants; there is no inferred transaction-wide merchant.

The production Merchants screen exposes New Merchant, Edit Selected, Save, Refresh, name/notes search, notes and active state, plus Return to Journal. Search/refresh retain unsaved drafts; New or selecting another record asks before discarding. Sortable/resizable/reorderable table and draggable split regions use company-owned saved state; overflow scrolls and visible text provides hover tooltips. VIEWER can read/search but cannot save or modify fields. Navigation appears under Accounting and in Journal.

No schema, accounting, SCLX format/import/export policy or processor settlement workflow change. P26-S6 owns settlement assistance. Acceptance: [S4C user testing](../P24-S4C-user-testing.md).

Narrow S4C prerequisite repair: Journal previously projected Merchant ID without its name when reopening a transaction, making inactive historical assignments blank. TransactionView now carries the current Merchant name; reference refresh carries company-owned retained Merchant labels separately from active choices. Resolve existing selections by ID against those labels, including a rename and deactivation in one save, without offering inactive merchants for new selection or changing mixed line assignments. Existing constructors remain compatible. Regression coverage belongs to this slice.
