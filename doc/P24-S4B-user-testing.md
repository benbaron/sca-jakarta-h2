# P24-S4B — Payee / Counterparty acceptance

Use the installed build from this slice on a disposable copy of a company. Record build commit, OS/display scaling, role, company and saved layout. Keep original accounting data protected by a full database backup.

1. Open **Payees / Counterparties** from Accounting navigation. Create a person and an organization with name, kind, email, phone and notes. Save, refresh and restart; verify all fields persist.
2. Rename a party used by a Journal entry. Reopen the entry: its Payee relationship retains the same identity and displays the new name. Existing supplemental counterparty narrative is not rewritten. Clear Active and save; the party remains visible in maintenance and historical entries but is omitted from new Payee choices. Reactivate it.
3. Attempt a duplicate name with different case or outer spaces, including an inactive name. Attempt blank/overlong names, email over 200 characters and phone over 40. Save fails visibly without altering the existing record. Distinct parties sharing a common name need distinguishable display names.
4. Start a new maintenance draft, filter the list, refresh and select another party. Cancel any discard prompt. Verify the draft remains. Choose New Payee, cancel, and verify it still remains. Confirm a deliberate discard and verify the selected/new form loads. Confirm table sorting works.
5. Start an unsaved Journal entry with line amounts, Fund/Event/Budget choices and a Payee. Open maintenance using the Journal button, create another party, and return to Journal. Verify refreshed choices, unchanged draft values and selected Payee ID. Rename and deactivate the selected party; return/refresh must retain its historical selection and draft.
6. Resize to laptop width and smaller, with increased display/text scaling and collapsed/expanded sidebars. Move both dividers. Scroll the table vertically and horizontally; use a wide column and enough rows to overflow. Scroll the header and editor in both directions when needed. All controls remain reachable; content never renders beneath sidebars. Hover clipped text.
7. Resize/reorder/sort columns and move dividers. Reopen the company and verify saved layout. Switch to another company and verify independent master records and layout. Return to the first company.
8. Sign in as VIEWER: search and view existing parties; New/Save/contact/lifecycle editing are unavailable. Confirm service rejection of unauthorized and cross-company saves in automated tests.
9. Check audit history for authenticated creation and edits, including before/after values. Export/import SCLX using the existing supported workflow: party identity/contact/active state and Payee links remain governed by the existing format. Do not expect this slice to change interchange compatibility.

Automated checks: CounterpartyAdminServiceTest covers validation, duplicate concurrency, ownership, authorization, audit and restart/history identity. CounterpartiesPanelTest covers maintenance draft protection, permissions, geometry and Journal refresh. CI includes both new JavaFX cases in its Xvfb gate. Native desktop acceptance remains a separate owner check; a skipped headless test is not a visual pass.
