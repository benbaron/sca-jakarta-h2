# P25-S5B — Independent functional expenses

Status VERIFYING. [PLAN](PLAN.md) owns execution; [adopted S5A](P25-S5A-functional-expense-contract.md) owns D07. AR = Events, OA = Administration, FR = Fundraising, explicit entry with no automatic defaults, net GL expense by canonical transaction date. No new product decision is required.

## Technical choices and scope

Add nullable `TxnSplit.expenseFunction` with stable AR/OA/FR enum/check constraint in a new nondestructive migration. Blank/legacy and current generated expenses without an explicit input stay Unclassified. AccountFunction, Fund, Event and Budget Category retain independent authority. Service validation rejects codes on nonexpense accounts before acceptance; corrections copy exact source facts, with normal permission/ownership/period/reconciliation/audit protection. Account maintenance/import cannot retype or invert the normal balance of an account with classified history; this directly prevents loss/sign changes in the adopted projection. Generic update cannot rewrite a classified inverse; use the existing correction/replacement route. User-entered mixed purposes use distinct canonical expense splits, never another monetary allocation ledger.

Native Journal create receipts retain byte-identical v1 hashing for commands without function facts. Classified commands use a versioned v2 normalized hash that includes every line's optional code; an accepted key cannot be reused with changed classification. Retained old request replay still acknowledges the current record without rewriting later corrections.

Journal uses one explicit Expense function choice per Entry Line, blank initially. The real shared Save Entry/File Save, dirty/draft retention, busy guard, copy/reload, permissions and company formatting/table/divider/scrolling remain authoritative. Debit/Credit edit and reload retain exact four-decimal command precision while company display stays formatted; the actual function-only Save regression reproduced and repairs a pre-existing rounding defect. No separate Save or configuration master is introduced.

The read-only Functional Expenses report uses actual canonical EXPENSE-account debit-minus-credit activity (including dated reversals) with company/date/Fund/Event scope, full AR/OA/FR/Unclassified and GL totals, gross unknown diagnostics, detail limits and transaction drill-through. Add typed Event filter support through the existing Report Library parameter contract; no extra report persistence. Unknown debit/credit offsets cannot imply complete classification.

Use a sparse version-1 `expenseFunctions` application extension keyed to intrinsic transaction-line IDs, rather than assigning strict new semantics to donor free-text usedFor or changing the supported core schema. Strict shape/code/expense-account/reference validation applies in serializer, preview and canonical commit. Classified values participate in existing complete transaction conflict identities; older absence preserves old unclassified hashes, changed/missing accepted values require explicit Keep target. Import/restart/exact retry/rollback preserve native receipt provenance and correction facts. Classified transaction/inverse export uses canonical split order, preserving mixed purposes on one account despite opposite amounts. No external consumer fidelity is asserted.

Inventory, fixed-asset depreciation/disposal/acquisition, reviewed bank acceptance and fund-transfer command paths currently supply no function input: their expense lines remain visibly Unclassified rather than receiving inferred defaults. Enumerate these writers and prove generated expenses/dated reversal preserve blank or explicitly accepted source facts; future explicit generator inputs must be carried without loss. Classification is held only on the canonical expense split.
