# P27-S3B1 — Snapshot review facts and external evidence references

After merged S3A, this slice records durable factual review history. S3B2 follows merge and owns serialization of all readiness sources with close-time revalidation. Existing PeriodCloseRangeService close/reopen operations remain unchanged here. A recorded review is not an approval, blocker waiver, independent document verification or authorization to close. Parent S3 stays incomplete.

Inspection found that company/row locks are inconsistent across all operational writers, while packet capture is deliberately a separate private backup. Do not imply that comparing its content revision provides an atomic close gate. Review records describe a captured historical snapshot, including unresolved blockers. Recompute the authoritative snapshot before recording and reject a changed preview, but make no claim that the live database cannot change afterward. S3B2 must prove its concurrency boundary before enabling close enforcement.

Reuse immutable H2 AuditEvent facts, as production opening conversion already does. Store action CLOSE_REVIEW_RECORDED, entity CloseReview, stable request UUID/portable identity, authenticated actor and event time, with a version-1 structured JSON after-value. The payload records period, content revision, captured backup hash/time, exact typed findings, external references, warning reasons and note. Limit the complete payload to the existing one-MiB audit/SCLX LOB capacity; reject overflow rather than truncating. No schema migration, attachment storage, approval queue, second ledger or policy engine is needed. Donor MonthlyCloseChecklistService was considered in S3A; its alternate/unwired authorities remain unsuitable.

Require an explicit self-attestation and at least one operator-supplied reference. Reference kinds are RECEIPT, EXTERNAL_REVIEW, COUNT_PACKET and OTHER; reference text is descriptive only and is never fetched or interpreted as a verified document. Do not require specific categories, signatures, deadlines or financial policy inputs. Recorded actor/time describe who saved the factual attestation, not a purported independent approver. Warn visibly that source documents remain external.

An optional exception reason must name a WARNING finding in the newly captured snapshot. Blockers cannot be excused. Saving a review with blockers remains available to record work performed, and those blockers remain visible. Reasons apply only to the retained finding/content revision and do not automatically carry to new snapshots or authorize closing. Inputs are normalized/bounded; duplicate reference identities and unknown/non-warning IDs fail. The request identity permits exact retry/restart and rejects conflicting reuse, including collisions with other audit operations. Successful Save adds one immutable audit fact and no ledger or close record; injected failures roll back entirely. Later corrections create a new review, never rewrite/delete history.

Period Close adds a Review Evidence tab with preview, reference/reason draft controls, explicit attestation, note, visible Save Review and selected-tab File/toolbar Save. New Review clears the draft deliberately; saved history is read-only with a retained-history explanation. Date changes invalidate the snapshot/reasons/attestation; company/database changes clear drafts to prevent cross-company reuse. Capture and Save run off-thread with busy/live permission gating. BOOKKEEPING_WRITE guards Save at the service boundary; EXPORT guards preview/history. Pending results for changed scope are discarded. Parent dirty/Save capabilities reflect the evidence editor even when history is selected.

Packet output includes review headers, external references, recorded findings and warning reasons for the exact requested company/period, labelled as facts recorded at snapshot capture. Their historical revisions are compared with the assessed accounting content, never treated as current certification. Exclude these review tables from the accounting content revision to avoid making Save invalidate its own reviewed snapshot. Audit's existing generic SCLX extension preserves the full structured payload and factual actor/time; imported revisions stay historical, and computed readiness is never import authority. P27-S4 remains the integrated portability gate.

Packet format accounting-4 identifies these four added tables. Review actor/time are read back from H2 after persistence so exact retries expose the same stored timestamp precision. A Save that completes after a scope change remains a fact about its original captured scope; the UI clears the current draft and directs the user to the original company's Audit History instead of claiming that Save was cancelled.

Tests cover populated references/reasons and blockers, exact retry/restart, conflicting identities, stale preview, malformed/oversize inputs, unknown/blocker reasons, Viewer denial and authenticated attribution, company/date isolation, rollback, historical revisions, packet parity, backup/SCLX audit preservation and actual JavaFX Save, permission/busy state, stale scope, dirty behavior, scrolling/layout and retained read-only history.

User checks: in a disposable company, select dates in Period Close and open Review Evidence. Preview; enter an external reference, optionally record a reason for a warning, explicitly attest and Save Review. Confirm actor/time, findings and references reload in history and the packet, without adding ledger/close entries. Reopen the application, choose the same dates and Refresh History to verify retention. Change a source fact, re-preview and verify the old record remains historical. Attempt a blocker reason and a Viewer Save; both must be unavailable/rejected. Inspect laptop layout and scroll/resize each region. Close enforcement remains the separately tracked S3B2 slice.
