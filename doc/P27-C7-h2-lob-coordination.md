The first 14 archives do not have this dangling reference. H2 2.4.240 writes LOB data, metadata and reference maps in separate operations. MVStore's physical-write lock does not exclude these in-memory mutations, so merely draining it can capture half an operation. A newer-engine-only diagnostic (2.5.252) fails on its first run with Chunk 7 not found, so an engine upgrade alone is rejected. No original evidence was reopened or changed.

Selected deliberate boundary: narrowly vendored, licensed patches to H2 2.4.240 LobStorageMap and MVStore, coordinating complete creation/copy/removal operations on its database's existing public LOB monitor. H2NativeSnapshot takes the same monitor before store commit, serialization/buffer-save drain and native file copy. Related metadata/reference changes also execute under the existing MVStore checkpoint lock, with reentrant auto-checkpoint deferred until the group is complete. Background LOB cleanup follows that order. Streaming data allocation remains incremental outside these bounded metadata groups. Source JDBC sessions/transactions stay open; writes involving LOBs may wait while a snapshot is copied. Parameter-stream LOB creation is covered even though JDBC setters run outside SQL command execution and session locks. Session/exclusive-mode locking is not used: it cannot cover those setters safely and can deadlock when SQL waits for another open transaction.

Architecture exception is deliberate: this is two attributed third-party H2 implementation classes in its required `org.h2` binary namespace, not application/domain code or another ledger. Existing app packages remain `org.nonprofitbookkeeping`. Vendor provenance, exact upstream hash, minimal patch and MPL license are under vendor/h2 and included in the app JAR. Upstream code style is retained for review. The existing non-Application FxMain launcher explicitly uses the classpath (not a split H2 module) so the override and dependency share one loader. Tests pin the actual engine version; dependency upgrades require an explicit patch review.
