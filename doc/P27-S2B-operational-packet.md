# P27-S2B — Operational accounting packet completion

Extends the [S2A snapshot/export](P27-S2A-core-packet.md) to deliver every section in the [generic packet contract](P27-S1-submission-contract.md). Reuse the same private backup, exact-decimal XLSX/CSV writer, authorization checks and non-overwrite publication. No official-template gate or new accounting policy is introduced.

Include enriched dated ledger rows with transaction/split IDs, Fund/Event/category/Merchant, function, payment facts, correction links and cleared-through-cutoff state. Include configured banks and baselines, period bank activity, all earlier outstanding lines through cutoff, recorded reconciliation sessions/differences and check exceptions. Session metadata describes recorded state at the captured snapshot, not an invented historical metadata version. Add a read-only session projection rather than calling the existing load method, which recalculates and saves balances.

Export all six supplemental schedules with opening/closing item balances, their canonical controls/gaps, period NMR/merchant summaries and movements, fixed-asset register/depreciation, inventory valuation/movements, custody history, retained budget versions/lines and active-version comparisons, Fund transfers and exceptions. Typed projection fields become CSV columns, nested record dimensions use qualified column names, and maps retain exact keyed decimal values. Empty sections retain schemas; missing sources are explicit exceptions. Inventory supplies remain distinguished by item type.

Budget comparison retains the existing canonical fiscal YTD basis, labelled with fiscal start and cutoff for each fiscal year overlapping the packet. All retained version identities/lines are exported; the active version at snapshot is explicitly identified for comparison. No active plan means unavailable comparison, not zero budget. Annual and monthly targets are not prorated or reinterpreted by packet export.

Full accounting lists retain the existing one-million-row ceiling. Existing asset/inventory/custody projections accept at most 5,000 rows: packet export conservatively rejects a result reaching that boundary instead of silently truncating. These are disclosed resource capacities; interactive report limits stay unchanged. Raw source rows, not similarly named free-text data, own identities. Preserve all Fund-transfer statuses and dated reversal links.

Exceptions include unmatched schedules, negative/unclassified items, unclassified expenses and missing Event tags, missing budget versions, bank differences/unfinished sessions, legacy unknown cleared dates, domain/GL discrepancies and recorded custody exceptions. Export remains available with exceptions and the manifest clearly marks it incomplete; even an exception-free export does not certify period close, external evidence review or signatures. Durable readiness/attestations remain P27-S3.

Inspection identified two presentation constraints handled within this slice: custody's interactive report evaluates overdue/corrections against current metadata, so packet reporting adds a separate cutoff-based projection while preserving the screen behavior; Excel manifest cells cannot hold arbitrarily many exceptions, so the workbook manifest references their dedicated full worksheet and JSON array. Fund-transfer reversals already have their own opposite-direction saved facts; export includes each once rather than synthesizing a second reversal.

Reconciliation supporting tables include statement and ledger/match rows with recorded-state column labels. Dated outstanding/cleared-through-cutoff fields remain separate. Existing opening-conversion preview checks supply orphan/baseline diagnostics without saving an acceptance. The donor semantic workbook service at `c697630e` still uses zero/empty placeholders; it is not imported. Production typed record projections and canonical dated-effect helpers supply all packet data. Packet format version `accounting-2` identifies the expanded sections; SCLX and persistence schemas are unchanged.

Required tests cover populated operational projections, earlier outstanding lines, cutoff/reversal effects, partial NMR/merchant settlement and observations, all-six schedule schemas/controls, assets/inventory/custody, budget identity/YTD, transfers, company isolation, rows beyond interactive limits, resource-capacity failure, consistent workbook/CSV/manifest contents and no source writes. Actual JavaFX tests cover the evolved accounting-packet action and factual success/exception status. Owner opens the generic workbook in a spreadsheet application and compares the same company/cutoff to canonical reports; that human result is recorded separately.

User checks: in a disposable company, open Report Library, set Packet start/end and choose **Export Accounting Packet (all funds/events)**. Extract the ZIP and open **Accounting Packet.xlsx**; compare Trial Balance, bank outstanding items (including items before the start), six schedules, NMR/merchant movements, assets/inventory/custody, budget version and transfers to their canonical reports for the same cutoff. Inspect **Exceptions and Notes** and the manifest; missing budget/bank sources must be explicit and the status must never certify close readiness. Compare a populated worksheet to its CSV, repeat with a historical cutoff and confirm the source reconciliation session, ledger and audit history remain unchanged. Confirm an existing destination is rejected and an account without EXPORT permission cannot export.
