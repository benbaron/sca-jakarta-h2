# P27-S2A — Core accounting packet export

S2 is split into reviewable vertical slices under the [generic contract](P27-S1-submission-contract.md). S2A exports Trial Balance, Balance Sheet, Income Statement, complete General Ledger and Functional Expenses into one ZIP containing XLSX, CSV supporting reports and a manifest. It is explicitly an **incomplete core packet**. Operational schedules, reconciliation, budgets, custody, supplemental/NMR/merchant detail and full ledger dimension/correction enrichment remain S2B; no complete-ready claim is made.

Capture a consistent H2 backup through the existing DatabaseTransferService, restore it only to a private temporary directory, and execute existing canonical report services against that isolated snapshot. Never publish the database backup, credentials, or other companies in the packet. Remove temporary databases after success/failure. Capture company, inclusive period, all-Fund/all-Event scope, creation time, application/packet version and backup SHA snapshot identity in the manifest. S2A supports company-wide scope only; report-list filters do not silently narrow it.

The ledger fetches up to one million rows plus one sentinel and rejects overflow before output. This avoids UI row limits; capacity is explicit. Preserve exact decimal strings in spreadsheet and CSV cells rather than converting financial values to binary floating point. CSV fields are quoted and spreadsheet-formula prefixes are escaped in text fields. XLSX cells are literal strings. No overwrite: choose a new destination, stage the complete ZIP alongside it and publish only after successful generation. Export requires the existing EXPORT permission at invocation and publication.

Unit coverage must verify canonical report totals, more than 500 ledger rows, company/cutoff isolation, precision, workbook/ZIP readability, missing-section manifest, failed/no-overwrite destinations and unchanged source ledger/audit data. Actual JavaFX checks exercise the production Report Library export action, permission gating and resulting status. S2B remains blocked until S2A merges.

Implemented coverage: `CoreAccountingPacketServiceTest` exercises the exported artifacts against canonical accounting fixtures, including year boundaries and capacity failures; `CorePacketExportActionTest` exercises actual asynchronous export and live permission/busy states; `ProductionPanelRouteComplianceTest` verifies that packet dates remain visible and independent when selecting as-of reports. Existing `FunctionalExpenseTest` retains regression coverage of the interactive report path. The action test is included in the actual-display CI selector.

Inspection found that the Functional Expenses screen renderer applies an interactive detail limit. S2A adds a separate complete rendering entry point over the same canonical result, preserving screen behavior and exporting every expense detail. A 501-line regression verifies complete detail, exact totals and visible Unclassified amounts. Donor inspection at `c697630e` found individual OFX and JavaFX table exports, not a compatible consistent multi-report packet; production report/backup authorities and existing Apache POI are reused instead.

Owner checks: open Report Library, set the always-visible **Packet start/end** dates, select Export Core Packet (all funds/events), choose a new ZIP path, inspect workbook/CSV/manifest and the explicit incomplete status, compare totals to reports, repeat to an existing destination and confirm refusal. Packet dates are independent of individual report dates and remain available when an as-of report is selected. Open XLSX in a spreadsheet application; record that human result separately.
