# P27-S3A — Factual readiness preview

First bounded part of [P27-S3](P23-P28-runbook-correction-program.md#p27-s3--add-factual-close-readiness-and-evidence-references-g3g5g13). S2 is merged. This slice adds a usable read-only preview in Period Close and matching packet diagnostics. S3B follows after merge and owns durable external evidence/attestations, warning-exception reasons and atomic close-time revalidation. Existing close/reopen policy is unchanged in S3A; preview never authorizes a close or certifies external review.

Inspection: production PeriodCloseRangeService owns date-range locks and factual close/reopen history, while the packet already owns private-snapshot canonical diagnostics. Donor `c697630e` MonthlyCloseChecklistService uses alternate gateways and explicit unwired checks; its checklist concept is useful, but those gateways and placeholder outcomes are not ported. Reuse production packet authorities. No persistence migration or new durable fact is introduced; SCLX remains unchanged in S3A.

Use the same company/date request, private H2 backup and canonical projections for packet export and preview. Factor capture rather than invoking export to a user-visible temporary ZIP or querying the changing live database separately. Require EXPORT permission before capture and again before returning results. Any missing source, projection failure or capacity limit fails visibly, never returns a successful empty checklist. Snapshots are private and deleted on all paths.

An immutable assessment contains company, inclusive activity range/cutoff, capture time, backup SHA, deterministic content revision and typed findings with stable identities. The content revision covers all unrounded packet tables, company and dates, not timestamps or backup bytes; it identifies assessed content rather than a database-wide concurrency token. Independent preview/export captures can differ; compare revisions before treating results as equivalent. Packet manifest and readiness table come from the exact same capture. No assertion of a current result after later edits is made.

Packet format `accounting-3` adds the Readiness Findings XLSX/CSV table and manifest content revision, automated status, blocker/warning counts and assessment basis. Existing full exceptions remain available. Finding identities hash severity, source area/reference and explanation; a changed fact receives a new identity rather than inheriting a previous exception reason.

Blockers are financial/control differences, unavailable required bank/budget/chart sources, unfinished recorded reconciliations, unknown historical clearing dates, unexplained allocations and Unclassified expenses. Warnings are missing Event tags, outstanding/unsettled balances, custody/count exceptions, instrument exceptions and nonfinancial transfers without a canonical transaction. Ordinary unsettled balances are review items, not presumed accounting errors. Use existing dated-control diagnostics without assuming every bank has a zero balance or all liabilities must be paid. Trial Balance and Balance Sheet differences are explicit blockers. Every finding carries an existing correction/review destination and its source reference; opening a destination does not imply a repair or apply hidden filters.

Statuses are **Blocked**, **Review required** and **No automated exceptions**. Even the last means only that the implemented automated checks found none. External receipt/approval/count-packet review, evidence attestation, allowed warning reasons and close-time recheck are not certified by this preview. No official-template, rate, filing or approval-system requirement is introduced.

Period Close retains its existing Save Closed Range and Reopen controls. A dedicated readiness tab exposes Preview Readiness and Open Selected Finding, a resizeable table with company-owned state, scope/revision/status and explicit no-certification text. Capture runs off the JavaFX thread with busy/permission gating. Date edits or company changes invalidate displayed results; a pending result for old scope is discarded. Errors clear earlier findings instead of leaving a misleading green result. Read-only preview has no Save operation.

Tests must cover financial/control blockers, ordinary unsettled warnings, classification/remediation routes, deterministic revisions and changed-content revisions, same-capture manifest/table parity, company/date isolation, capacity failures, denied access, no source writes, and actual JavaFX asynchronous completion, busy/live permission state, navigation and stale-scope invalidation. Existing accounting tests continue to cover the underlying domain scenarios.

User testing: open Period Close in a disposable company, select dates, open Readiness and Preview. Compare company/dates and findings with the accounting packet for the same scope and revision. Select a finding and open its canonical review/correction screen. Correct source data, preview again and confirm the revision/findings change. Edit either date while preview is pending and verify old results are discarded. Inspect at laptop size, scroll/reorder columns and reopen to confirm saved table layout. No preview should close a period, change reconciliation state or add audit events. External evidence and close enforcement remain the next slice.
