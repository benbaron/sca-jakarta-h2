# Old-engine native recovery fixtures

The standalone `H2OnlineBackupProbe.java` is a separate synthetic diagnostic for
the [C11 CI storage blocker](../../../../../doc/P29-C11-ci-recovery-blocker.md).
It does not generate or replace the frozen old-engine archives below. Run it
explicitly with the current H2 jar; timing-dependent stress is not a JUnit gate.
For the corrected runtime, use `java -ea -cp <h2-2.4.240.jar> H2OnlineBackupProbe.java safe-close`:
this applies MAX_COMPACT_TIME=0 and additionally verifies explicit full compaction,
restart contents and absence of a storage trace for every copy. The bounded
production-backup JUnit regression separately retains every CLOB character.

## Previous-runtime compatibility image

`h2-2.5.252-v92.zip` is an additional offline native backup, created with actual
H2 **2.5.252** / Flyway **13.12.0** and `NativeRecoveryFixture.populate` from
merged seed `ec4d358f4568dbf6ee689fe3356f0ad0a7817400`. Its SHA-256 is
`985d8e86f7d51a943c6013c81e658009d46942c9faa15cbfa6d4785dbcf14470`.
The accompanying JSON records all 66 public tables' original columns, row counts
and complete sorted-row digests, plus the guard inventory. It was generated
before changing the dependency for [P27-C2](../../../../../doc/P27-C2-online-backup-integrity.md).
It verifies normal in-place opening as well as validated restore under the
selected runtime; it is not a claim that every arbitrary newer-engine database
can be downgraded safely. Only synthetic fixture data is included.

To reproduce in a disposable checkout of that seed with its original runtime,
build the test/runtime classpath, then run the two supplied source helpers:

```text
java -cp <2.5.252-seed-test-classpath> Generate252Backup.java <absent-db-base> <absent-hot.zip> <absent-offline.zip>
java -cp <2.5.252-seed-test-classpath> Generate252Manifest.java <db-base> <offline.zip> <manifest.json> ec4d358f4568dbf6ee689fe3356f0ad0a7817400
```

The helpers require engine 2.5.252; retain Flyway 13.12.0 too. The online archive
is only a generation diagnostic and is not the frozen compatibility image.
Generated UUIDs/times change bytes; never regenerate this archive or its oracle
during ordinary tests. Do not alter the original 2.2.224 fixtures below.

## Original 2.2.224 images

All data is synthetic. No uploaded database, real person, production credential or referenced external document is included. The password credential belongs to the synthetic `recovery-only-user`; its source password is explicit in the seed fixture.

- `h2-2.2.224-v92.zip` is an offline native H2 backup after all source connections closed.
- `h2-2.2.224-hot-affected.zip` retains the earlier hot native backup that exposed old-image/secondary-page problems. It must preserve the same original fields and usable indexed lookups after the accepted runtime's isolated-copy finalization.
- `h2-2.2.224-v92.json` records H2 2.2.224, Flyway 10.17.0, schema V92, seed revision, both ZIP SHA-256 values, original column names and exact sorted-row digests/counts for all 66 public tables, plus the complete trigger inventory. The table digests cover every original field, including intrinsic IDs, request hashes, raw audit payloads, credentials, preferences and compatibility rows. They do not merely hash an export generated by the new engine.

The source was seeded from `IntegratedPortabilityFixture` at [7ca0bfe6](https://github.com/benbaron/sca-jakarta-h2/tree/7ca0bfe6d5ea2cbbe7f8e75ec57a4c1fc4f002a8), before the runtime dependency upgrade. The affected ZIP SHA is `f9d973e4ba92dcb9c052a5f969216f9a643dc8b36676a0016d021c4fc99d7073`. `NativeRecoveryFixture` retains that source graph for the new-stack regression without replaying the parked production/SCLX fixes.

To regenerate in a disposable worktree, use that historical seed revision and its original dependency versions. Run `mvn -DskipTests test-compile`, generate a test/runtime classpath (including target/test-classes and target/classes), then launch the supplied Java source helpers on that classpath:

```text
java -cp <historical-test-classpath> GenerateLegacyBackup.java <absent-db-base> <absent-hot.zip> <absent-offline.zip>
java -cp <historical-test-classpath> GenerateLegacyManifest.java <db-base> <offline.zip> <manifest.json> <seed-commit> <hot.zip>
```

The helpers refuse the wrong H2 runtime; the seed/backup helper refuses existing destinations. Preserve the old Flyway version too. The manifest helper uses nullable length-prefixed JDBC string values in original column order, sorts complete rows and hashes their newline-joined UTF-8 encoding; triggers are sorted by name/event/table/orientation/timing. Use only the fresh synthetic source. The old engine may itself reproduce the failure during generation; never conceal that failure by generating a supposedly old fixture with the new engine.

Generated UUIDs and times make regenerated bytes different. Replace both archives and the manifest together, record provenance and intentionally review the new hashes. Never regenerate these fixtures during normal tests or silently refresh expected digests to accept data loss. Runtime upgrade tests copy archives to disposable paths, preserve the original bytes, compare every original column/row/trigger, restart and exercise indexed lookups, write guards and identity allocation.
